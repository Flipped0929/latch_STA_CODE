# S298 行为级理论复现（v1）

这个文件夹把 S27 的“延迟约束 + 锁存器时序 + 行为交叉检查”方法迁移到更大的 `s298` 电路上。当前版本只做理论和行为级分析，不包含真实 FPGA、布局布线、门级网表或器件寄生参数。

## 复现了什么

原始数据来自：

```text
latch_STA_CODE_direct/benchmark/s298.blif.out
```

`prepare_s298_data.py` 将原始延迟表整理成两张表：

- `data/s298_edges.csv`：时序约束使用的内部边。
- `data/s298_output_taps.csv`：连接到 `OUTPUT` 的观测抽头。抽头只用于观测，不能参与反馈，所以没有放入锁存器约束图。

整理规则与 S27 的数据规则一致：所有 `INPUT` 源映射为公共节点 `IO`；重复的源-目标边取 `Dmax` 的最大值和 `Dmin` 的最小值；`Dmin>Dmax` 的数据直接报错。

本次数据得到 **15 个时序节点（含 IO）和 78 条聚合内部边**。

需要区分两种结果：仓库原 C++ 程序的解析器会把 `OUTPUT` 也映射成 `IO`，所以它的 S298 图是 15 个节点、84 条边（其中 6 条是输出抽头回到 `IO` 的边）。仓库已经记录的原程序 Howard/LP-MCR 基线见 `../../tests/results/2026-10-11-phase2/final-results.csv`：默认参数下为 `11.3642504215 ns`，四个全局锁存器参数设为 `0.1 ns` 时为 `11.5642504215 ns`。本文件夹的主结果沿用 S27 行为验证的语义，把输出抽头单独保存、不让它们反馈到状态图，并使用 `H=0.10 ns` 的三类 ELL 差分约束。因此下面的 `10.89558999 ns` 是 **S27 理论验证方法迁移到 S298 的结果**，不能直接写成原 C++ Howard/LP-MCR 的复现值。

## 算法

对每条 `u -> v` 边检查三类差分约束：

```text
setup          T       - Dmax - su + sv >= 0
extended setup T + W   - Dmax - su + sv >= 0
hold           Dmin-H-W + su - sv >= 0
```

其中 `H=0.10 ns` 是统一的 hold 要求，`su/sv` 是两个节点的时序偏移。脚本把同一方向上的平行约束保留为最紧的一条，用 Bellman-Ford 检查是否存在负环，并通过二分搜索得到：先最小化周期 `T`，再在这个周期下最大化透明窗 `W`。

这里的两阶段搜索有单调性依据：普通 setup 约束不含 `W`，extended setup 会随 `W` 增大而放松，hold 会随 `W` 增大而收紧。因此最小周期可在 `W=0` 求出，固定最小周期后再求最大可行 `W`。

## 当前结果

结果保存在 `results/summary.json`、`results/edge_slacks.csv` 和 `results/behavior_crosscheck.json`：

| 指标 | 结果 |
| --- | ---: |
| 最小理论周期 `T` | `10.89558999 ns` |
| 最大透明窗 `W` | `0 ns` |
| hold 要求 | `0.10 ns` |
| 最小逐边静态裕量 | `0 ns`（数值容差内） |
| 最紧边 | `G14 -> G16` |
| `T/2-W` 裕量 | `5.447794995 ns` |
| 行为模式 | 14 个代表性 8 周期模式 |
| 行为通过 | `14 / 14` |

行为复核使用每条时序边的 `Dmax` 做 XOR 时序图仿真，并以 `100 ns` 慢周期作为参考，允许恒定流水线偏移。它同时单独检查 `IO` 捕获值是否等于输入激励。这个结果是图级功能诊断：S298 的原始门逻辑没有从 benchmark 中重建，`OUTPUT` 抽头也没有纳入状态等价判定，因此行为通过率不能解释为完整门级功能正确率。

## 延迟扰动与重新调度

`run_s298_sensitivity.py` 进一步复现了 S27 ver.4 的问题：分别把所有 `Dmax` 和 `Dmin` 乘以 `-10%、-5%、0、+5%、+10%`，共 25 个组合；每个合法组合都比较“固定 nominal 时序方案”和“知道延迟变化后重新优化”的结果。`Dmin>Dmax` 的 10 个组合被标记为非法，不参与重新优化。

| 指标 | 结果 |
| --- | ---: |
| 扰动组合总数 | `25` |
| 合法组合 | `15` |
| 非法组合 | `10` |
| 固定方案静态通过 | `1 / 15` |
| 重新优化后静态通过 | `15 / 15` |
| 固定方案行为通过 | `93 / 210` |
| 重新优化后行为通过 | `210 / 210` |
| 重新优化周期范围 | `9.81603099–12.31366099 ns` |
| 重新优化透明窗 | 所有合法点均为 `0 ns` |

这个实验说明，在当前抽象模型里，延迟变化后离线重新选择周期和节点偏移可以恢复静态可行性；它不表示电路可以在线自动调参。

`results/original_cpp_reference.csv` 保存了仓库原 C++ Howard/LP-MCR 的四个已记录参考点，便于和本文件夹的迁移模型结果并排查看。

## 如何重新运行

在本目录执行：

```powershell
python prepare_s298_data.py
python run_s298_v1.py
python run_s298_sensitivity.py
python -m unittest discover -s tests -v
```

如果系统没有配置 `python`，可使用本机的 Python 解释器替换命令。运行后应重新生成 `data/` 和 `results/` 中的结果文件。

## 这一版的意义和局限

这一版已经把 S27 的静态差分约束检查推广到了更大的反馈图，并给出了可重复的周期、偏移和逐边裕量结果，能够回答“在当前理论延迟图下，S298 是否存在一组可行时序参数”。

它还没有回答真实电路的门级功能、布局布线后延迟、时钟抖动、亚稳态、功耗或器件资源问题。`W=0` 说明在当前 S298 聚合延迟数据和 `0.10 ns` hold 要求下，最小周期点没有可用的正透明窗；后续可以研究更保守/更精细的延迟模型、输出抽头行为和更接近原始门逻辑的功能模型。
