# S27 理论时序优化报告（ver.2）

## 结论

ver.2 在静态差分约束模型中，对周期 `T`、透明窗 `W` 和各节点 skew 联合求解，并把每条延迟边的保持裕量要求设为 `0.10 ns`。在本报告列出的假设下，得到：

| 参数 | ver.2 结果 |
| --- | ---: |
| 最小周期 `T` | `5.060700 ns` |
| 最优点透明窗 `W` | `0.390990 ns` |
| `IO` skew | `0 ns` |
| `G5` skew | `1.523130 ns` |
| `G6` skew | `0.825490 ns` |
| `G7` skew | `0.706630 ns` |
| 全部边最小剩余裕量 | `0 ns`，刚好达到约束边界 |

这里的“最优”是一个明确的两级目标：先在所有约束下最小化 `T`，再在最小 `T` 的解中最大化 `W`。它是当前静态模型内的数学结果，不代表真实 FPGA 或门级电路已经验证通过。

把该组参数回灌到 ver.1 的事件仿真器后，周期 80–159 的状态和输出抽头匹配率均为 100%，IO 自检通过；同一范围的动态 hold 检查也通过，最差边为 IO→G7，可用保持时间正好为 `0.10 ns`。完整运行记录见 `results/behavioral_crosscheck.txt`。

| 项目 | ver.1 做法与不足 | ver.2 改进 |
| --- | --- | --- |

| 正确性检查 | 主要靠有限窗口内的功能仿真和有限组输入；可发现部分错误，但不能覆盖所有边和所有输入变化。 | 将每条边的最大延迟 setup、扩展 setup 和最小延迟 hold 条件转成差分约束，并通过全部有向环的约束检查全局可行性。 |
| 保持要求 | `hold_check.py` 是有限激励下的动态观测。`lat_Wsafe_lp` 在 `T=5.057 ns, W=2.5285 ns` 时观测到的最小保持裕量为 `0.08532 ns`，低于本次采用的 `0.10 ns` 目标；这组观测不能证明其他转换也满足要求。 | 对所有 10 条聚合边显式施加 `0.10 ns` 保持裕量，并同时优化周期、透明窗和 skew。结果表中的 hold 值是扣除该要求后的剩余裕量，全部非负，最小值为 0。 |
| `T`、`W` 与 skew 的选择 | 采用预设窗口 `W=min(T/2, 2.6138)` 和已有 skew 表，没有在保持约束下重新联合求解。 | 直接求解 `T` 和 `W`，再从差分约束恢复节点 skew；在 `T=5.0607 ns` 时可用的最大 `W` 是 `0.39099 ns`。 |
| 最小周期的解释 | 有限扫描在 `T=5.057 ns` 附近通过；这个数值低于 G6 自环延迟 `5.06070 ns`，不能据此推翻自环给出的静态周期下界。 | 静态模型明确包含 G6 自环 setup 约束 `T >= 5.06070 ns`；求解器达到该下界，因此在声明的模型内证明了最小 `T`。 |
| 复现性 | 结果依赖仿真脚本中的硬编码参数、扫描步长和随机激励。 | 输入边表、求解程序、输出表和单元测试全部随本报告放在 ver.2；求解器只使用 Python 标准库。 |

两版的 `T` 不能当成同一种测量直接比较：ver.1 的 `5.057 ns` 是有限行为仿真的扫描边界；ver.2 的 `5.06070 ns` 是静态差分约束的最小周期。ver.2 高 `0.00370 ns`（3.70 ps），换来的是明确的全边保持约束和可复算的静态可行性证书。

## 为什么透明窗缩小了

G6 自环的 setup 约束给出硬下界：

```text
T >= Dmax(G6->G6) = 5.06070 ns
```

在这个最小周期处，IO→G5 的最大/最小延迟与 `0.10 ns` 保持要求形成联合约束：

```text
T - W >= Dmax(IO->G5) - Dmin(IO->G5) + 0.10
       = 6.58383 - 2.01412 + 0.10
       = 4.66971 ns
```

所以 `T=5.06070 ns` 时 `W` 不能超过 `0.39099 ns`。跨 G6→G5、IO→G6 与 IO→G5 的另一条约束环也在该点取等号。可见只按 G7 自环选窗口上限不够；窗口还受输入路径和跨级路径共同限制。三条活跃约束保存在 `results/active_cycles.csv`。

## 求解模型

每条原始时序边 `u→v` 建立三类节点时间差约束。节点时间记为 `s`，输入参考节点 `IO` 的 skew 固定为 0：

```text
setup:           Dmax + s_u - s_v <= T
extended setup:  Dmax + s_u - s_v <= T + W
hold:            W + 0.10 - s_u + s_v <= Dmin
```

setup 和 hold 约束构成带权有向图。每一个有向环都必须满足相应的线性不等式；优化器枚举这个四节点图的全部 108 个简单环，得到关于 `T`、`W` 的半平面，再检查这些半平面的交点以求全局最小 `T`。随后用差分约束的势函数恢复一组 skew，并逐边重算 slack。`results/edge_slacks.csv` 保存所有边的复核结果。

### 与仓库 ELL 实现的关系

约束形式来自仓库的 ELL / `ellLP` 实现：`include/timing_oracle.hpp` 中有三类边权，`src/LP.cpp` 中可见对应的 setup、扩展 setup 和 hold 不等式。ver.2 做了三项有意区分：

1. 原 `ellLP` 的目标是最小化 `T+W`，ver.2 的目标是最小化 `T`，并把最大化 `W` 作为次级目标。
2. ELL oracle 把 `Tsu`、`Th`、`Tcq`、`Tdq` 写为 0；ver.2 仍假设 `Tsu=Tcq=Tdq=0`，但额外把 `0.10 ns` 当作统一的理论 hold 裕量。这个数值是本次分析的设计要求，不是从某个器件手册得到的规格。
3. ELL oracle 限制 `W<=T/2`，`ellLP` 本身没有加入这个限制；ver.2 明确加入 `W<=T/2`。

另一个图语义差异需要保留在结论里：仓库 parser 把 `INPUT` 和 `OUTPUT` 都折叠到 `IO`，因此输出抽头也会进入 ELL 图；ver.1 行为仿真把输出当作观察端，不作为反馈边。ver.2 为了与 ver.1 的 S27 行为模型一致，采用 `IO` 作为输入源，并将 `OUTPUT` 抽头排除在反馈时序图之外。因此本结果不是对当前仓库原始 ELL 图的数值复现；后续若要与工具输出逐项比较，需先统一输入/输出边界语义。

`Dmax` 和 `Dmin` 按端点对分别取最坏最大值和最坏最小值，它们可能来自不同物理路径。这样的组合用于保守静态约束，不代表同一条路径同时具有这两个延迟。

## 复现

需要 Python 3.9 或更新版本，不需要第三方库。在 ver.2 目录运行：

```powershell
python optimize_s27.py
python -m unittest discover -s tests -v
python ..\ver.1\sim.py 5.0607 --W 0.39099 --skew 1.52313 0.82549 0.70663 --hold 0.10
```

优化器重新生成 `results/` 下的 JSON 和 CSV；测试检查静态约束和求解证书的一致性。最后一条命令在 ver.1 的有限仿真模型中复核优化参数。

## 结论边界与未验证项

- 事件仿真只比较固定激励和有限周期窗口；100% 匹配不是对任意输入序列的穷尽功能证明。动态 hold 检查也依赖激励和捕获窗口，静态约束表承担全边最坏情况检查。
- 仍是理论时序图模型，不含亚稳态、时钟不确定度、脉冲宽度限制、实际单元参数或真实布局布线延迟。
- 当前实现为小图枚举简单环，适合 S27 这种四节点模型；扩展到大图时应改用 LP 求解器或负环分离方法，并独立验证。
- 仓库 ELL 与行为仿真的 IO 边界语义尚未统一；与工具比较前需先解决这一点。

因此，ver.2 的成果是：在明确写出的 S27 静态理论模型下，给出一组满足全边 `0.10 ns` hold 裕量的最小周期方案，并提供可复算的数据与约束检查；再用 ver.1 事件仿真器对该参数组作有限窗口交叉验证。它仍不是实际电路或后布局布线验证。
