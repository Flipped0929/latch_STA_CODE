# S27 理论交叉验证 ver.3

ver.3 是在电脑上可以完成的“更接近实际验证”的理论推进：把 ver.2 求出的静态时序方案送回 ver.1 事件仿真器，用可重复的输入、边界扫描和延迟扰动反复检查。它同时报告“数学约束通过”和“行为模型跑通”，不把有限仿真误写成真实 FPGA 或后布局布线结果。

## 为什么要做 ver.3

| 版本 | 主要做法 | 还缺少什么 |
| --- | --- | --- |
| ver.1 | 用一组随机激励做有限窗口事件仿真，并观察功能和动态 hold。 | 输入覆盖有限，参数边界和延迟变化没有系统列出；动态 hold 只能看到被激励的边。 |
| ver.2 | 把 10 条聚合延迟边写成差分约束，联合求 `T/W/skew`，证明 nominal 点满足静态 setup、extended setup 和 hold。 | 主要证明数学模型可行，只有一次有限行为回灌，缺少系统的模式、边界和敏感性证据。 |
| ver.3 | 256 个 8 周期模式、81 个 `T/W` 临界点、25 个延迟扰动点、5 个 hold 要求点，并把静态与行为结果逐项落盘。 | 仍使用 XOR 时序图行为模型，不含门级逻辑、真实器件库或布局布线寄生。 |

因此 ver.3 的成果不是重新发明一个优化器，而是给 ver.2 的理论结论增加可重复的交叉证据，并明确指出静态分析与有限行为仿真不一致时应如何解释。

## 本次结论

在 ver.2 的 nominal 参数下：

| 参数 | 数值 |
| --- | ---: |
| 周期 `T` | 5.06070 ns |
| 透明窗 `W` | 0.39099 ns |
| skew（IO、G5、G6、G7） | 0、1.52313、0.82549、0.70663 ns |
| 统一 hold 要求 | 0.10 ns |

nominal 点通过了全部 **256 个** 8 周期重复输入模式，状态匹配率最低仍为 100%，IO 输入自检也全部通过。这里的 256 个模式是 8 位模式的全部组合；每个模式在仿真中循环重复。它覆盖了所有 8 周期周期性激励，但不等于原始 S27 门级网表的任意长度输入穷举。

T/W 临界网格为 `9 x 9 = 81` 个点：T 在 `T* ± 0.02 ns` 范围内取点，W 在 `W* ± 0.10 ns` 范围内取点。固定 ver.2 的 skew 后，静态约束通过 25 个网格点；每个网格点用 14 个代表性确定性模式做行为检查，行为通过点为 69 个。分类为：静态和行为都通过 25 点、静态失败但有限行为通过 44 点、两者都失败 12 点，没有出现静态通过而行为失败的点。静态失败而行为通过不是矛盾：有限激励没有覆盖所有最坏边界，不能推翻静态约束。

延迟敏感性把 `Dmax` 与 `Dmin` 分别按 -10%、-5%、0、+5%、+10% 缩放，共 25 个组合。每个组合固定 nominal `T/W/skew`，同时把缩放后的 `Dmax` 送入功能行为模型，把缩放后的 `Dmin` 送入动态 hold 诊断。由于真实延迟区间必须满足 `Dmin <= Dmax`，其中 10 个组合产生了非法区间，结果明确标为无效，不能计入通过率；15 个合法组合中只有 nominal 点仍满足这个固定时序安排的全部静态约束。这是“固定方案对延迟变化不鲁棒”的证据，不是说重新优化后一定无法通过。

hold 要求敏感性使用 `0、0.05、0.10、0.20、0.30 ns` 重新检查 nominal 方案：前 3 个要求通过，`0.20 ns` 和 `0.30 ns` 失败，说明当前 `W=0.39099 ns` 的保持裕量边界就在约 `0.10 ns`。

## 文件

- `validate_s27_v3.py`：主脚本。读取 `ver.2/data/s27_edges.csv` 和 `ver.2/results/summary.json`，动态加载 `ver.1/sim.py`，生成全部结果。
- `tests/test_validate_s27_v3.py`：标准库 `unittest` 测试，检查 256 模式生成、nominal 静态可行性、周期边界失败和行为对照接口。
- `results/pattern_results.csv`：256 个模式逐行结果，包括恒定周期偏移、G5/G6/G7 状态匹配率、抽头匹配率和 IO 自检。
- `results/boundary_grid.csv`：81 个 T/W 网格点的静态裕量和 14 个代表模式的行为通过统计。
- `results/perturbation.csv`：`Dmax/Dmin` 独立缩放的 25 个固定方案敏感性点，包含扰动后的功能行为和动态 hold 诊断，以及非法延迟区间标记。
- `results/hold_sensitivity.csv`：5 个代表点的动态保持诊断。
- `results/hold_margin_sensitivity.csv`：5 个 hold 要求值下的静态和动态保持结果。
- `results/summary.json`：总计数、参数、输入边表 SHA-256 和浮点容差。
- `make_figures.py`：只用 Python 标准库把 CSV 生成 SVG 图。
- `figures/`：T/W 边界、延迟扰动、动态 hold 和 hold 要求的可视化结果。

## 如何复现

在 ver.3 目录执行（只使用 Python 标准库）：

```powershell
python validate_s27_v3.py
python -m unittest discover -s tests -v
python make_figures.py
```

结果会写入 `results/`，图写入 `figures/`。如果只需快速重新生成 nominal 与保持诊断，可使用 `--skip-grid --skip-perturbation`；完整交付结果应使用默认命令。

## 判定口径和限制

1. 行为模型沿用 ver.1：四个节点 `IO/G5/G6/G7`，每条输入边的值用 XOR 汇合，输出抽头只观测不反馈。它是时序图行为模型，不是原始 S27 门级逻辑，也没有真实布局布线寄生参数。
2. 快时钟与 `T=30 ns` 慢时钟参考共用同一条周期输入。允许一个恒定的 capture-cycle 偏移；G5/G6/G7 的最小匹配率达到 99.5% 才算行为通过，IO 必须逐拍等于激励。抽头匹配率只作为诊断。
3. 事件同刻顺序沿用 ver.1：数据到达优先于开窗，开窗优先于关窗；关窗时刻到达按 `Tsu=0` 处理。静态边界使用 `1e-8 ns` 数值容差，所以理论上 0 slack 的 nominal 点显示为约 `-1e-16` 仍判定通过。
4. `hold_sensitivity.csv` 和 `hold_margin_sensitivity.csv` 调用 ver.1 的 `MIN_DELAY` 动态诊断和固定随机种子 2701。它们只统计实际激励产生的翻转；“dynamic pass”不替代静态全边 hold 约束。静态检查才是对 10 条聚合边的全边检查。
5. 网格和扰动均固定 ver.2 的 skew、周期和窗口，没有对每个新点重新优化；因此不能把网格外的通过点解释为新的最小周期证明。延迟扰动图是 fixed schedule；若未来重新优化，应另称 retuned 并单独报告。
6. `Dmax` 与 `Dmin` 是端点聚合区间，可能来自不同物理路径；它们用于保守理论约束，不等于一条物理路径同时取两个极值。仓库 ELL 还把 INPUT/OUTPUT 折叠到 IO，而本行为模型把输出抽头作为观察端，二者不能直接宣称数值完全复现。

这组结果支持的结论是：ver.2 的 nominal 静态边界在 ver.1 XOR 行为模型的 256 个 8 周期模式下可复现通过，并且 T/W 临界附近的失败方向与 setup/hold 静态裕量变化一致。它仍然是理论验证，不能替代真实芯片、FPGA 或布局布线后的门级仿真。
