# S27 理论成果：行为级验证迭代

本目录是 S27 理论验证成果的 GitHub 提交包。它把四个迭代版本、输入数据、脚本、测试、结果表和图统一整理在一起，便于他人阅读和复现。

这里验证的是锁存器时序模型在行为级仿真中的可行性，不包含真实 FPGA、门级网表、布局布线寄生或上板测量。

## 迭代内容

| 版本 | 主要工作 | 形成的结论 |
| --- | --- | --- |
| `ver.1` | 建立 XOR 时序图事件仿真器，分别比较边沿触发寄存器和带透明窗口的锁存器，并补充最小延迟保持检查 | 寄存器方案最小周期约为 `6.58383 ns`；锁存器方案可达到约 `5.0607 ns`，说明透明窗口能够吸收部分长路径延迟 |
| `ver.2` | 将 S27 延迟图整理为 10 条聚合边，建立差分约束和简单环枚举求解，联合优化 `T`、`W` 和逐锁存器 skew | 得到 `T=5.06070 ns`、`W=0.39099 ns` 的名义解；共检查 108 个简单环，最小边裕量为 0 |
| `ver.3` | 增加 256 个确定性功能模式、`T/W` 边界网格、`Dmax/Dmin` 扰动和保持裕量敏感性分析 | 名义参数下 256/256 个模式通过；81 个边界点中静态约束通过 25 个、行为点通过 69 个；25 个延迟扰动中有 15 个合法点 |
| `ver.4` | 对每个合法延迟扰动重新求解 `T/W/skew`，并与固定名义方案进行对照 | 固定方案静态通过 1/15、行为通过 93/210；重新优化后静态 15/15、行为 210/210，说明离线重新调度可以恢复理论可行性 |

名义解使用的逐锁存器 skew 为：`G5=1.52313 ns`、`G6=0.82549 ns`、`G7=0.70663 ns`、`IO=0 ns`。

## 目录结构

每个版本都保留了自己的说明、源码和结果：

- `ver.1/`：行为级仿真、保持检查、原始工具输出和第一版报告。
- `ver.2/`：约束优化器、`data/s27_edges.csv` 延迟边数据、边裕量和求解结果。
- `ver.3/`：多模式功能交叉验证、边界/扰动/保持敏感性结果及图表。
- `ver.4/`：延迟扰动后的重新优化、固定方案与重新优化方案的对比结果及图表。

其中，`ver.1/data/s27.blif.out` 是输入数据来源快照，`ver.2/data/s27_edges.csv` 是用于约束求解的规范化聚合边数据；`results/` 保存逐点结果，`figures/` 保存可直接用于汇报的图表，`tests/` 保存标准库单元测试。

## 复现方法

环境要求：Python 3.12。核心仿真和优化只使用 Python 标准库；运行 `ver.1/sweep.py` 出图时需要安装 `ver.1/requirements.txt` 中的 matplotlib。

在本目录下按版本进入对应文件夹运行：

```powershell
Set-Location ver.1
python sim.py 6.0 --mode ff
python -m unittest -v test_hold.py

Set-Location ..\ver.2
python optimize_s27.py
python -m unittest discover -s tests -v

Set-Location ..\ver.3
python validate_s27_v3.py
python -m unittest discover -s tests -v

Set-Location ..\ver.4
python retune_s27_v4.py
python -m unittest discover -s tests -v
```

如需重新生成图表，分别在 `ver.1`、`ver.3` 和 `ver.4` 目录运行各自的 `sweep.py` 或 `make_figures.py`。

## 结论边界

本成果说明的是：在给定的 XOR 行为模型、最大/最小延迟、理想时钟和锁存器窗口假设下，S27 存在满足约束的理论时序参数，并且延迟变化后可以通过离线重新选择参数恢复可行性。

模型没有覆盖真实门级逻辑、标准单元参数、时钟抖动、亚稳态、边沿速率、脉冲宽度限制、布局布线寄生或 FPGA 实测。因此，结果应表述为“理论模型的行为级交叉验证”，不能直接表述为硬件已经通过验证。

`ver.3` 和 `ver.4` 中的行为检查使用有限的确定性模式；最终判断仍以静态逐边约束结果为主，行为仿真作为独立的交叉证据。工具参考输出来自不同版本的捕获文件，若更换工具代码版本，应重新生成参考输出并更新结果。
