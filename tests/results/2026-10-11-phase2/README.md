# 第二阶段：Howard 鲁棒性增强

## 本次改动

1. 使用 Boost 强连通分量划分，对含环分量分别运行 Howard。孤立节点、无后继节点和无环部分不再导致整个图报 InvalidPolicy；完全无环时返回 NoCycle。
2. 在原图中保留关键环边，检查关键环首尾闭合、总 transit 和环比值残差。
3. 在选定全局环比值后，对全部边检查差分约束，覆盖跨分量连接和无环节点。仅检查最优分量是不够的，测试中包含“各分量单独可解、合并后约束冲突”的反例。
4. 输出含环分量数、策略迭代次数、最大约束违反量和关键环比值残差。校验失败不导出有效周期或关键环。
5. 保留原有占空比、非零锁存器参数、逐锁存器覆盖和诊断报告。LP 仍作为独立参考；未修改或运行 YTO。

## 实际验证

验证环境：Windows 下的 Ubuntu/WSL，GCC 13.3.0、Boost 1.83、GLPK 5.0。

| 检查 | 结果 |
| --- | --- |
| 主程序重新构建 | 成功 |
| 完整 CTest | 7/7 通过，见 ctest.log |
| 随机小图与独立简单环穷举对照 | 200/200 通过 |
| 地址、内存泄漏和未定义行为检查 | 图测试通过，未报告异常 |
| 31 个 benchmark 的四种配置 | 124/124 通过，无超时 |
| 与上一阶段 Howard 周期的最大差 | 0 ns |
| Howard 与 LP 周期的最大差 | 1.4210854715202004e-14 ns |
| 全图最大约束违反量 | 2.7755575615628914e-17 |
| 关键环比值最大残差 | 4.163336342344337e-17 |

四种配置为：默认 50% 占空比、40% 占空比、四个全局参数均为 0.1 ns、40% 占空比下首个非 IO 锁存器四个参数均覆盖为 0.1 ns。

周期对照容差为 `1e-4 + 1e-8 * max(abs(T_Howard), abs(T_LP))` ns。
约束违反量与关键环比值残差分别使用 `1e-10` 阈值，二者不是同一个物理量。

`raw-results.csv` 保留运行器原始输出；`final-results.csv` 将诊断字段展开，并加入与上一阶段周期的差值。上一阶段文件未覆盖。构建与复现命令见 `tests/README.md`。

## 测试中发现并修正的问题

- 原版本在“有效自环加孤立节点”上返回 InvalidPolicy，新增测试已验证修复。
- 本轮实现初稿只把关键节点距离重置为零，导致一个六节点样例迭代停滞。保留当前距离偏移后通过，并将该样例单独固定为回归测试，避免依赖随机样例顺序。

## 尚存限制

- 遇到总 transit 不大于 eps 的策略环，仍返回 UnsupportedCycle。这不等于电路无解，也没有穷尽所有混合符号 transit 情况。
- ConstraintViolation 表示当前候选未通过数值检查，不将它直接解释成一般性的不可行证明。
- 全图检查最坏耗时 O(VE)，分量初始化也有额外成本。本阶段没有证明性能提升；测试耗时包含 LP，不能当作 Howard 单独耗时。
- 图上的势函数用于检查差分约束，并未作为物理时钟偏斜输出。
- 小图穷举和 benchmark 一致性不能替代物理模型正确性的验证，尤其不能代替实际工艺、波形和电路级验证。

建议下一阶段进行占空比及非零参数的系统扫描，结合关键环和活跃约束分析周期变化原因，再决定时钟与数据通路联合优化的变量和目标。
